# GUIDE: Widget Visibility Profiles (ComfyUI)

Этот гайд описывает, как работает `web/widget_visibility_profiles.js`, какие у него ограничения и как быстро диагностировать проблемы, когда в ноде остаются "следы" скрытых параметров.

## Что делает расширение
- Назначает profile-правила для конкретных нод.
- Скрывает/показывает виджеты по значению управляющего виджета (например `seam_model`).
- Удаляет/восстанавливает input-слоты скрытых параметров.
- Пересчитывает layout и размер ноды после переключения режима.

## Где настраивается
- Файл: `web/widget_visibility_profiles.js`
- Профили задаются в `VISIBILITY_PROFILES`.

Поля профиля:
- `targetNodes`: имена нод, к которым применяется профиль.
- `controllerWidget`: виджет-переключатель режима.
- `groups`: группы параметров для скрытия/показа.
- `modes`: какие группы видимы в каждом режиме.

## Жизненный цикл
1. В `beforeRegisterNodeDef` расширение ищет совпадение `nodeData.name` с `targetNodes`.
2. Патчит `onNodeCreated` и `onConfigure`.
3. На создание/загрузку ноды вызывает `applyProfileVisibility(...)`.
4. Оборачивает callback управляющего виджета и повторно применяет профиль при смене режима.

## Как устроено скрытие
- Виджет:
  - сохраняется его исходное состояние (`type`, `hidden`, `computeSize`, `serialize`, `serializeValue`);
  - затем ставится `hidden=true`, `type="converted-widget"`, `computeSize=() => [0, -4]`.
- Input-слот:
  - ищется по `slot.widget.name` или `slot.name`;
  - если есть активный линк, он отключается;
  - слот удаляется из `node.inputs`;
  - при обратном показе слот восстанавливается из сохраненного snapshot.
- Layout:
  - пересчитываются `widget.last_y`;
  - затем пересчитывается `node.size`.

## Почему могут оставаться "следы"
- Ограничение ComfyUI/LiteGraph: некоторые типы виджетов рисуются нестандартно и не полностью следуют `computeSize`.
- Виджет может состоять из нескольких связанных частей (`linkedWidgets`); если часть создана нестандартно, пустое место может остаться.
- Коннектор может выглядеть "залипшим", если другой плагин модифицирует те же слоты после нашего профиля.
- При загрузке старого workflow порядок/состав `inputs` может отличаться от ожидаемого snapshot.

## Важно про подключения
- Скрытие входа разрывает существующий линк этого параметра намеренно.
- Это компромисс: либо "чистая" скрытая UI-зона, либо сохранение подключения.

## Чеклист диагностики
1. Убедиться, что `targetNodes` содержит точное имя ноды из `nodeData.name`.
2. Проверить, что `controllerWidget` реально есть в `node.widgets`.
3. Сверить имена из `groups` с фактическими `widget.name`.
4. Переключить режим и проверить, что callback управляющего виджета срабатывает.
5. Убедиться, что скрываемые слоты реально исчезают из `node.inputs`.
6. Проверить, не патчит ли другой extension те же `onNodeCreated/onConfigure`.
7. После изменений обновить страницу ComfyUI с очисткой кэша браузера.

## Практические ограничения
- Полностью "идеальное" динамическое сжатие UI в ComfyUI не всегда достижимо для всех кастомных виджетов.
- Наиболее надежный UX-путь для сложных режимов: отдельные ноды по режимам (как сделано для Seam Match v1/v2/v3/v4).
