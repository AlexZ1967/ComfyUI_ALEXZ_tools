# Silent Film Cadence — руководство

## Назначение

Нода моделирует виртуальную съёмку с пониженной кадровой частотой, циклической неравномерностью ручки и экспозиционным размазыванием движения. Это художественная модель, а не точная реконструкция конкретного киноаппарата. Пресеты ниже — рекомендуемые стартовые настройки; они не обязательно совпадают со значениями новой ноды по умолчанию.

## Когда использовать

- Нужно изменить скорость и пластику движения под немую проекцию.
- Нужно увидеть циклическую неравномерность ручного привода и добавить связанное покачивание камеры.
- Нужно компенсировать известное замедление исходника либо сохранить число кадров при стилизации.

## Минимальный сценарий (3 шага)

1. Подайте видео и укажите частоту его интерпретации в `source_fps`.
2. Выберите режим воспроизведения и `cadence_model=hand_crank`, примените умеренный пресет ниже.
3. Передайте `image` и `cadence_json` в Finish, затем соберите видео с выбранным fps в Combine.

Соберите цепочку:

```text
Video Load.image → Silent Film Cadence.image → Silent Film Finish.image → Video Combine.images
                   Cadence.cadence_json      → Finish.cadence_json
```

О параметрах завершающего слоя см. [руководство Silent Film Finish](GUIDE_VIDEO_SILENT_FILM_FINISH.md). Сначала настройте скорость и каденс с выключенным Finish, затем размытие, затем покачивание и финальную обработку. Для сравнения вариантов фиксируйте `seed`: у соответствующего управления после генерации выберите `fixed`, а не `randomize`.

## Сначала выберите скорость воспроизведения

Частоту готового файла задаёт **Video Combine**, а не название режима Cadence. Вход `IMAGE` не хранит fps; `source_fps` нужно задавать самостоятельно.

| `playback_mode` | Что получается | Как собирать файл |
|---|---|---|
| `preserve_duration_25fps` | Число выходных кадров совпадает с входным. Меняются фазы движения и их распределение; при ненулевом blur кадры внутри группы не обязательно полностью одинаковы | Для сохранения длительности ставьте в Combine фактический fps входного батча |
| `undercrank_projected_25fps` | По одному выходному кадру на виртуальную экспозицию. При пониженном виртуальном fps батч становится короче, движение при проекции ускоряется | Для предлагаемых здесь пресетов ставьте Combine **25 fps** |

**В режиме `preserve_duration_25fps` значение `source_fps=48` само по себе не ускоряет видео вдвое.** Если на входе 241 кадр, на выходе тоже 241. При Combine 25 fps это 9.64 секунды независимо от выбранной временной шкалы расчёта. Для ускорения с уменьшением количества кадров нужен `undercrank_projected_25fps`.

Приблизительный расчёт для ускоренной проекции:

```text
N — число входных кадров
Fs — source_fps, то есть частота интерпретации входа
Fv — средний виртуальный fps внутри target_fps_min/max
Fp — fps в Video Combine

Число выходных кадров ≈ N × Fv / Fs
Длительность готового файла = число выходных кадров / Fp
```

Дрейф скорости, seed и неполный последний интервал влияют на округление. Проверяйте фактический `output_frame_count`.

### Если исходник замедлен вдвое

Для 24 fps клипа с уже встроенным замедлением ×2 можно интерпретировать весь батч как 48 fps, выбрать `undercrank_projected_25fps`, диапазон 18–20 и собрать на 25 fps. Из 241 кадра получится примерно 95–96, то есть около 3.8 секунды вместо исходных 10 секунд. Помимо компенсации замедления это даёт дополнительное ускорение проекции.

Удвоение `source_fps` здесь намеренное, это не реальный fps файла. Используйте его только если исходник действительно замедлен; не добавляйте одновременно ещё одну ноду ускорения ×2. Для обычного 24 fps материала оставьте `source_fps=24`: при том же диапазоне 18–20 результат будет примерно 7.6 секунды.

## Параметры

### Вход и скорость

| Параметр | Значение и влияние | Рекомендуемый старт |
|---|---|---|
| `image` | Батч RGB/RGBA в формате THWC. Порядок кадров должен соответствовать времени исходника | Декодированное видео без предварительной интерполяции |
| `source_fps` | Частота интерпретации батча. В ускоренной проекции большее значение даёт меньше выходных кадров; в режиме сохранения кадров не меняет их число | Реальный fps исходника; 48 только для намеренной компенсации замедленного ×2 исходника с fps 24 |
| `playback_mode` | Выбирает сохранение кадров или ускоренную проекцию; см. раздел выше | `undercrank_projected_25fps` для пресетов ускоренного немого кино |
| `target_fps_min` | Нижняя граница виртуальной скорости съёмки | 18; 16 для более выраженного эффекта |
| `target_fps_max` | Верхняя граница виртуальной скорости. Увеличение обеих границ делает ускоренную проекцию медленнее; уменьшение — быстрее | 20 |

Средний уровень диапазона задаёт общий темп. Его ширина задаёт доступный размах пульсации. Например, 18–20 и 12–26 имеют одинаковую середину, но второй диапазон намного сильнее меняет скорость в пределах оборота. Не меняйте одну границу наугад: это одновременно меняет и средний темп, и размах.

### Ручка и движение камеры

| Параметр | Значение и влияние | Рекомендуемый старт |
|---|---|---|
| `cadence_model` | `hand_crank` — цикл ручки; `legacy_random` — прежний сглаженный случайный дрейф | **`hand_crank`**; по умолчанию оставлен `legacy_random` для совместимости |
| `fps_drift_strength` | Сила изменения скорости: 0 — постоянная середина диапазона; 1 — полная заданная амплитуда. Чем больше, тем заметнее ритмическое ускорение и замедление | 0.6–0.8; 1 для демонстрации |
| `crank_irregularity` | Неровность среднего темпа между оборотами. 0 — точно повторяющийся цикл; увеличение добавляет плавный дрейф, но не заменяет цикл шумом | 0.10–0.25; 0 для наглядного теста |
| `camera_shake_strength` | Нерегулярные толчки, кивки и наклоны камеры от усилия на ручке, без повторяющейся синусоиды. Увеличение усиливает движение и его экспозиционный смаз | 0.15–0.30; 0–0.10 для устойчивой камеры; 0 при проверке только скорости |
| `seed` | Начальная фаза ручки, нерегулярность скорости и рисунок усилий/поправок камеры; не является силой эффекта | 1925, управление после генерации `fixed` |

При равных границах fps либо `fps_drift_strength=0` пульсации скорости нет. При этом ручка продолжает вращаться: ненулевая `camera_shake_strength` всё ещё может покачивать камеру.

Пульсация скорости и покачивание — разные сигналы. Скорость может циклически повторяться, но камера не должна описывать одинаковую петлю на каждом обороте. В модели покачивания оборот создаёт возможность усилия: его момент, направление, сила и длительность восстановления меняются по `seed`. Иногда оборот проходит спокойно, иногда возникают два усилия. Короткий толчок сменяется более медленным плавным возвратом, а среднее положение постепенно меняется, как при поправке хвата. Накопленного бесконечного дрейфа и независимого случайного скачка на каждом кадре нет.

`crank_irregularity=0` делает регулярной **скорость ручки**, но не возвращает синусоидальную траекторию камеры. Новых регуляторов покачивания нет: используйте прежний `camera_shake_strength` и seed. После изменения модели прежний seed даёт другой рисунок покачивания; каденс и его последовательность fps сохранены. Для оценки нового движения временно поставьте `gate_weave_px=0` в Finish.

Модель использует фиксированные **8 кадров на оборот**. Скорость ручки автоматически связана с fps: при 16 fps это примерно 2 оборота в секунду виртуальной съёмки, при 20 — примерно 2.5. В ускоренной проекции на 25 fps оборот занимает 8/25 секунды, поэтому пульсация повторяется примерно 3.1 раза в секунду экранного времени. Сам выходной файл всё равно имеет постоянные 25 fps: меняется движение между кадрами.

`crank_frames_per_turn` — скрытое устаревшее поле совместимости. Сохранённое значение игнорируется, используется 8. Его техническое место оставлено, чтобы значения остальных виджетов старых workflow не сдвигались.

Сила покачивания задаётся относительно размера изображения и примерно сохраняет относительный размах на уменьшенном preview. Движение учитывается **внутри экспозиции до усреднения**, а не добавляется простым сдвигом готового кадра. Это приближение движения в плоскости изображения, без восстановления глубины и параллакса; края заполняются граничными пикселями.

`gate_weave_px` в Finish отвечает за другую причину нестабильности — проекцию. Его не нужно увеличивать вместо покачивания камеры. В `legacy_random` настройки ручки скрыты, покачивание не применяется.

### Размытие и качество

| Параметр | Значение и влияние | Рекомендуемый старт |
|---|---|---|
| `shutter_fraction` | Доля виртуального интервала для экспозиции. Больше — длиннее смаз, меньше — резче движение | 0.65; 0.35–0.45 для более отчётливой пульсации |
| `motion_blur_strength` | Дополнительный множитель ширины экспозиции. Увеличение смягчает рывки и двоение, но может скрывать ритм и детали | 0.8; 0.5 для теста ритма; 0 для отключения экспозиционного размытия |
| `blur_mode` | `simple` — смешивание соседних кадров, быстрее, но может двоить контуры. `flow_integrated` — промежуточные деформации по optical flow с проверкой надёжности | `flow_integrated`; сравните с `simple` на проблемных перекрытиях |
| `blur_samples` | Число отсчётов внутри экспозиции. Больше — плавнее траектория смаза, но дольше расчёт; это не отдельная сила размытия | 9 на GPU, 5–7 для быстрых проб; 1 означает один отсчёт без интегрирования экспозиции |

Ширина экспозиции в основном определяется произведением `shutter_fraction × motion_blur_strength` и длительностью виртуального кадра. В ноде есть минимальная ширина экспозиции при ненулевой силе: один `shutter_fraction=0` не гарантирует полного отключения blur. Для этого используйте **`motion_blur_strength=0`** или `blur_samples=1`. Интерполяция дробной позиции кадра при этом остаётся.

Слишком сильный blur превращает ускорение и замедление в ровный smear. Сначала уменьшайте ширину экспозиции, а не увеличивайте силу ручки до предела. Flow не гарантирует идеального результата на тонких оградах, волосах, быстрых объектах и перекрытиях: в ненадёжных областях применяется обычное смешивание.

### Устройство расчёта

`compute_device=auto` — рекомендуемый режим. Он использует CUDA для кадров площадью от 256×256 пикселей, если ComfyUI выбрал CUDA и хватает VRAM. Маленькие кадры остаются на CPU. `cpu` выбирает CPU для сравнения; `cuda` явно запрашивает GPU, но при недоступности CUDA или нехватке VRAM используется CPU с сообщением в консоли.

Farneback остаётся на CPU в OpenCV. Деформации, проверка согласованности потока, смешивание, интегрирование и покачивание ускоряются на GPU. Новая модель и CUDA-сборка OpenCV не нужны. Между CPU и GPU возможны небольшие различия округления.

## Decision helper

Ниже — готовые пресеты для разных задач. Меняйте скорость, пульсацию и размытие по отдельности.

### Умеренный образ немой проекции

| Параметр | Значение |
|---|---|
| `source_fps` | Реальный fps исходника: обычно 24 или 25 |
| `playback_mode` | `undercrank_projected_25fps` |
| `cadence_model` | `hand_crank` |
| `target_fps_min/max` | 18 / 20 |
| `fps_drift_strength` | 0.65 |
| `crank_irregularity` | 0.15 |
| `camera_shake_strength` | 0.25 |
| `shutter_fraction` | 0.65 |
| `motion_blur_strength` | 0.8 |
| `blur_mode`, `blur_samples` | `flow_integrated`, 9 |
| `compute_device` | `auto` |
| `seed` | 1925, `fixed` |
| Video Combine fps | 25 |

Получится умеренное ускорение и небольшая циклическая неравномерность. Для более сдержанного результата сузьте диапазон до 18–19 и уменьшите силу до 0.4–0.5. Для более заметного — диапазон 16–20 и сила 0.8.

### Для клипа Kling с предполагаемым замедлением ×2

Используйте предыдущий пресет, но **`source_fps=48`** для исходного 24 fps файла. Сохраните `undercrank_projected_25fps` и Combine 25 fps. Пример для 241 кадра: около 3.8 секунды на выходе. Если слишком быстро — поднимите границы до 20–22; если всё ещё медленно — опустите до 16–18. Это подбор под предположение о замедлении ×2, а не определение скорости по метаданным.

### Наглядно увидеть пульсацию

От умеренного пресета измените:

| Параметр | Значение |
|---|---|
| `target_fps_min/max` | **12 / 24** |
| `fps_drift_strength` | **1.0** |
| `crank_irregularity` | **0.0** |
| `camera_shake_strength` | **0.0** |
| `shutter_fraction` | **0.35** |
| `motion_blur_strength` | **0.5** |

Для замедленного Kling оставьте `source_fps=48`, для обычного видео — фактический fps. Сохраните `hand_crank`, `undercrank_projected_25fps`, 9 отсчётов и Combine 25 fps. На время сравнения обойдите Finish, зафиксируйте seed. Должно быть видно ритмическое ускорение и замедление движения, особенно всадников и других быстро перемещающихся объектов. Это намеренно преувеличенный диагностический пресет.

### Сохранить длительность обычного видео

Выберите `preserve_duration_25fps`, укажите **реальный fps** в `source_fps` и тот же fps в Combine. Остальные настройки умеренного пресета можно сохранить. Не используйте этот режим для компенсации рапида только изменением `source_fps`.

## Порядок настройки

1. Без Finish выберите `playback_mode`, `source_fps` и fps Combine; проверьте длительность.
2. Подберите среднюю скорость диапазоном `target_fps_min/max`.
3. Подберите пульсацию его шириной и `fps_drift_strength`; сначала ставьте нерегулярность 0.
4. Установите ширину экспозиции. Добавьте отсчёты, если смаз выглядит ступенчатым.
5. Добавьте небольшую нерегулярность и покачивание; затем подключите Finish.

## Типовые ошибки и решения

| Симптом | Что изменить |
|---|---|
| Видео всё ещё замедлено при `source_fps=48` | Проверьте режим: для ускорения нужен `undercrank_projected_25fps`, не сохранение всех кадров |
| Скорость слишком высокая | Поднимите обе границы виртуального fps |
| Не видно неравномерности | Проверьте `hand_crank`, ненулевую силу и разные границы; временно примените диагностический пресет и уменьшите blur |
| Картинка сильно дёргается | Сузьте диапазон, уменьшите силу; затем немного добавьте экспозиционного смаза |
| Двоение контуров | Сравните `flow_integrated` с `simple`; проверьте быстрые объекты и перекрытия |
| Flow изгибает тонкие детали | Уменьшите ширину экспозиции и сравните с `simple` |
| Слишком заметна тряска | Уменьшите `camera_shake_strength`; отдельно проверьте `gate_weave_px` в Finish |
| Каждый запуск выглядит по-разному | Поставьте один seed и `fixed` у обеих нод и у внешнего генератора seed, если он подключён |

## Интерпретация выходов

`image` — обработанный батч; `cadence_json` — описание виртуальных экспозиций и синхронизации. Передавайте оба выхода в соответствующие входы Finish.

| Поле `cadence_json` | Как читать |
|---|---|
| `input_frame_count`, `output_frame_count` | Фактическое число кадров до и после |
| `average_effective_fps`, `group_count` | Средний виртуальный fps и число экспозиций |
| `fps_values_preview`, `fps_values_full` | Скорость каждой виртуальной экспозиции; здесь виден циклический рисунок |
| `output_group_ids`, `group_sizes_preview` | Соответствие выходных кадров виртуальным экспозициям и размеры групп |
| `cadence_model`, `crank_irregularity`, `crank_frames_per_turn` | Модель, нерегулярность и фиксированное передаточное отношение |
| `camera_shake_strength`, `actual_camera_shake_strength`, `capture_motion_model` | Заданное и реально применённое покачивание |
| `compute_device`, `actual_compute_device` | Запрошенное и фактическое устройство |
| `actual_blur_mode` | Фактический алгоритм, включая `simple_fallback_no_cv2` без OpenCV |
| `phase_biases_full` | В `hand_crank` нулевые: независимое случайное смещение центра экспозиции не добавляется |

**`output_duration_seconds`, `output_fps` и `recommended_video_combine_fps` текущей ноды рассчитаны по `source_fps`.** Они не знают реальную настройку Combine. Для готового файла считайте длительность по `output_frame_count / fps Combine`, особенно при намеренных 48 fps интерпретации и 25 fps кодирования.

## Производительность

В консоли `[Silent Film Cadence]` видны четыре этапа: проверка, построение каденса, экспозиционная обработка, завершение батча и JSON. На этапе 3/4 обновляется одна полоса `tqdm` с кадрами, процентами, скоростью и ETA. При ошибке полоса закрывается; «Готово» выводится только после успешного результата.

GPU получает небольшое окно кадров, а не весь ролик. Кадровый и flow-кэши ограничены четырьмя записями. Выход сразу заполняет один батч на исходном устройстве, без списка готовых кадров и дополнительных копий через `stack`. При нехватке VRAM обработка продолжается на CPU с сообщением; модели ComfyUI не выгружаются автоматически.

Это ограничивает рабочие буферы, но сам входной и выходной `IMAGE`-батчи всё равно занимают память. Большое разрешение, длинный клип и сохранение всех кадров требуют больше RAM. Сначала проверяйте настройки на коротком фрагменте, затем запускайте полный ролик. Альфа-канал поддерживается и участвует в тех же преобразованиях и экспозиционном усреднении.
