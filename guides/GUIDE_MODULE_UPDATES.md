# Обновление модулей с проверкой зависимостей

В Module Node Picker расширена кнопка **Refresh Custom Nodes Info**. После установки
этой версии перезапустите ComfyUI: новые Python routes регистрируются при запуске.
ComfyUI должен работать в Conda-окружении `p313-torch214-cu132`.

## Проверка и статусы

Нажмите **Refresh Custom Nodes Info**: она проверяет upstream и зависимости,
а затем обновляет каталог и прежние маркеры изменений без повторного Git fetch.
После завершения остаётся короткая плашка с количеством найденных обновлений
и кнопкой **«Подробнее»** рядом. Подробный отчёт скрыт до её нажатия; повторное
нажатие сворачивает его. Открытие панели ничего не устанавливает и не проверяет
upstream автоматически. Отдельная кнопка проверки зависимостей удалена.

Backend получает точный upstream commit через Git. Fetch добавляет Git-объекты,
но не изменяет рабочие файлы, HEAD и FETCH_HEAD; remote-tracking ref обновляется,
чтобы прежний каталог использовал тот же результат проверки. Нужны отдельный Git-репозиторий,
настроенный upstream и возможность fast-forward. Локальные изменения блокируют
апдейт; автоматические stash/reset/checkout веток не выполняются.

Текущее ограничение: проверка считает локальными изменениями любой результат
`git status --porcelain --untracked-files=all`. Сюда входят не исключённые автором
модуля Python-кэши `__pycache__/*.pyc`, runtime-конфигурация, служебные файлы
установщика и отличия нормализации переносов строк Git. Это не доказывает ручную
правку исходников. Даже такие файлы в этой версии блокируют апдейт; они не удаляются
и не исключаются автоматически. Отдельное исправление классификации должно
сохранить защиту реальных правок и незарегистрированных пользовательских файлов.

Сравниваются requirements текущего и целевого commit, включая локальные вложенные
`-r`/`-c`. Изменения `install.py`, `setup.py`, `setup.cfg`, `pyproject.toml`, а также
изменение requirements при наличии `install.py` требуют отдельной проверки.
Install scripts никогда не запускаются.

Если декларации уже удовлетворяются установленными пакетами, pip не запускается.
Иначе backend выполняет `pip install --dry-run --report`, закрепляя **все
существующие версии** constraints-файлом. Разрешены только wheels из PyPI.
Используется `--no-deps`: дочерние зависимости читаются из wheel metadata и
проверяются до следующего прохода resolver. Dry-run не получает transitive
URL/VCS requirements и не запускает их build backend. Editable, внешние includes,
нестандартные параметры pip и исходные сборки требуют отдельной проверки.

Backend проверяет предполагаемый граф всего окружения, Python/platform markers
и запрошенные extras. Исходные metadata-конфликты выводятся отдельно от новых.

- **Конфликтов не обнаружено**: существующие версии сохраняются; допустимо
  добавление совместимых wheel-зависимостей.
- **С риском**: нужна замена защищённого пакета, изменился packaging/install
  script или найдены новые конфликты.
- **Проверка не завершена**: ошибка Git/сети, detached HEAD, отсутствующий upstream,
  неподдерживаемые декларации или недоступный wheel. Это не доказанный конфликт.
- **Заблокировано**: есть локальные изменения.
- **Актуально**: установлен целевой commit.

В разделе **«Подробнее»** показываются все модули, commit до/после, diff requirements,
причины и новые пакеты. Общая
кнопка **«Обновить проверенные (X)»** появляется только после совместной проверки
всего набора. При конфликте набора индивидуальные проверенные апдейты доступны,
но массовая кнопка отсутствует.

Оценка не гарантирует работоспособность нового кода и не проверяет бинарный ABI
старых пакетов, системные библиотеки, CUDA kernels, импорты и поведение нод.

## Выполнение

1. Раскройте **«Подробнее»**, нажмите **«Апдейт»** у проверенного модуля либо общую кнопку. Подтверждение
   показывает выбранные модули и добавляемые пакеты.
2. План поставится в очередь. Пока ComfyUI работает, worker ничего не обновляет.
   Доступна **«Отменить ожидающее обновление»**.
3. Сохраните workflow и **остановите ComfyUI**. Не используйте автоматический
   restart: worker должен закончить до следующего запуска сервера.
4. Смотрите `.alexz-updates/<plan_id>/status.json`, например командой
   `cat .alexz-updates/<plan_id>/status.json`. Дождитесь `phase: done`.
   `error` означает незавершённое обновление; прочитайте сообщение.
5. Запустите ComfyUI, проверьте startup log и выполните
   [browser smoke](GUIDE_BROWSER_SMOKE.md).

Worker повторно проверяет срок плана (час после анализа), HEAD, отсутствие
локальных изменений и fingerprint окружения. Применяется зафиксированный commit
через fast-forward с отключёнными Git hooks. Новые upstream commits не
подхватываются автоматически. Перед добавлением пакетов создаётся backup через
`conda create --clone` в каталоге задания. При ошибке backup обновление не начинается.
Затем скачиваются wheels из pip report с проверкой SHA256; установка выполняется
без повторного resolver: `pip install --no-index --no-deps <проверенные wheels>`.

Проверяются сохранение старых версий, добавленные версии и новые metadata-конфликты.
При ошибке код возвращается на старый commit только если не появились новые правки.
pip не транзакционен: после частичной установки восстановите окружение из
`environment-backup`, указанного в сообщении. Резервный commit сохранён в
`refs/alexz-backups/<plan_id>` каждого обновлённого репозитория.

## Апдейт с риском

**«Апдейт только кода…»** доступен отдельно для рискованных/непроверенных модулей,
если Git допускает fast-forward. Подтверждение сообщает, что зависимости останутся
прежними и модуль может перестать загружаться. Этот апдейт тоже ждёт остановки
ComfyUI и не запускает pip/install scripts.

Принудительная замена конфликтующих пакетов рабочего окружения не реализована.
Такие обновления следует отдельно проверять в копии окружения. Backup перед
проверенными добавлениями не является проверкой рискованного апдейта в копии.

## API и ограничения

- Core ComfyUI не обновляется. Legacy update/install routes остаются info-only/advisory.
- `/alexz_tools/update_plan_{status,check,apply,cancel}` доступны loopback-клиенту
  с локальным Host и совпадающим Origin. POST требует JSON и `X-Alexz-Update: 1`.
- Worker поддерживает POSIX, исключает параллельные задания и отказывается
  выполнять план, если ComfyUI снова запущен на том же порту. Это дополнительная
  проверка, а не блокировка запуска сервера: соблюдайте порядок запуска выше.
- `.alexz-updates/` исключён из Git. Он содержит задания, статусы и backup,
  который может занимать значительное место.
- [update_planner_smoke.js](../tests/browser/update_planner_smoke.js) проверяет
  UI на подменённых API-ответах без реальных апдейтов. Это не заменяет проверку
  новых routes в настоящем ComfyUI после перезапуска.

Для проверки нового UI сначала выполните основной browser smoke в отдельной
тестовой вкладке по `GUIDE_BROWSER_SMOKE.md`, затем в той же вкладке вызовите
Playwright MCP `browser_run_code_unsafe` с `filename`:
`tests/browser/update_planner_smoke.js` (при необходимости абсолютный путь).
Ожидается `status: PASS` и шесть проверок. Новые API-запросы и локальное обновление
каталога со сбросом маркеров подменяются; сценарий проверяет `sync_upstreams=false`.
Остальные операции изменения ALEXZ backend блокируются. Native confirm временно
подменяется только в тестовой вкладке и восстанавливается после сценария.
После проверки закройте только тестовую вкладку.
