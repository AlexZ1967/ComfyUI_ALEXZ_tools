# Dev-запуск ComfyUI для ALEXZ_tools

## Назначение

Скрипт [scripts/start_comfyui_dev.sh](../scripts/start_comfyui_dev.sh) запускает установленный ComfyUI с четырьмя разрешёнными custom-node пакетами: **ComfyUI_ALEXZ_tools**, **ComfyUI-VideoHelperSuite**, **comfyui-manager** и **ComfyUI-Crystools**. Этого достаточно для [поэтапного Silent Film workflow](../workflows/Видео-в-Хронику-по-этапам.json): общий seed и окна Preview Image входят в ComfyUI core. Новый поэтапный workflow использует собственные Load Source Video и Save Final Video; VideoHelperSuite оставлен для прежних workflow. Crystools добавляет монитор CPU/GPU, RAM/VRAM, температуры GPU и диска.

Профиль использует штатные флаги `--disable-all-custom-nodes --whitelist-custom-nodes`. В установленном ComfyUI они проверяются и в `main.py:execute_prestartup_script`, и в `nodes.py:init_external_custom_nodes`. Поэтому у исключённых пакетов не исполняются даже prestartup scripts. Отключается также загрузка партнёрских API-нод через `--disable-partner-nodes`; интернет-доступ frontend этим не блокируется.

ComfyUI core, обычный start_comfyui.sh, каталоги расширений и их состояние включения не изменяются. Фильтруются пакеты, а не отдельные классы: все ноды ALEXZ_tools остаются доступны. Встроенные ноды ComfyUI продолжают загружаться.

## Когда использовать

- Разработка Python-нод с частыми перезапусками ComfyUI.
- Проверка Silent Film без долгой инициализации остальных установленных расширений.
- Сравнение поведения с обычным полным запуском.

Если проверяете интеграцию с конкретным сторонним пакетом, добавьте его явно. Manager включён в базовый профиль для кнопки Restart. Его установленный обработчик `/manager/reboot` сохраняет `sys.argv` при перезапуске, поэтому порт и белый список не теряются. Кнопку Restart во время проверки скрипта автоматически не вызываем.

При обновлении списка пакетов закройте текущий dev-процесс и запустите скрипт или ярлык заново: Restart уже работающего экземпляра сохраняет прежние аргументы. После запуска обновите страницу. Показатели и интервал монитора настраиваются в **Settings → Crystools**; `Refresh per second=0` отключает монитор (несмотря на название, значение задаёт интервал в секундах). Для разработки удобно 1–2 секунды. Числа относятся к машине сервера ComfyUI: RAM — системная занятость, GPU/VRAM — данные NVIDIA, а не только расход конкретной ноды. Для наблюдения за дисковым кэшем выберите в настройках HDD раздел, где находится `.alexz-video-cache/`. Ноду в workflow для отображения монитора добавлять не нужно.

## Минимальный сценарий (3 шага)

1. В терминале проекта посмотрите команду: `bash scripts/start_comfyui_dev.sh --dry-run`.
2. Остановите обычный ComfyUI, если он занимает 8188, и запустите `bash scripts/start_comfyui_dev.sh`.
3. Откройте `http://127.0.0.1:8188`, загрузите поэтапный workflow и продолжайте разработку. После изменений Python остановите процесс через Ctrl+C и повторите ту же команду.

Второй экземпляр на другом порту:

```bash
bash scripts/start_comfyui_dev.sh -- --port 8189
```

Откройте `http://127.0.0.1:8189`. Скрипт не останавливает работающие экземпляры автоматически. Второй экземпляр использует ту же установку, модели, input/output и пользовательские workflow; это отдельный процесс, но не отдельное хранилище настроек.

## Память длинного видеопайплайна

Dev-скрипт больше не добавляет `--cache-none`. В Silent Film сохраняются **только Load Source Video и Camera**: при повторном запуске они используются повторно, если не изменились входы. Быстрые этапы и следующие за ними превью/сборщики пересчитываются; их батчи освобождаются после последнего потребителя. Остальные независимые ноды ComfyUI используют штатное кэширование. Явные `--cache-ram`, `--cache-classic`, `--cache-lru` и `--cache-none` передаются ComfyUI без изменения.

ALEXZ_tools распределяет полные видеобатчи между **VRAM → RAM → диском**. VRAM используется с запасом под фактическую рабочую порцию (не больше числа кадров); если выход там не помещается, проверяется RAM. В RAM сохраняется запас не меньше 4 ГиБ либо CPU-буферов плюс 512 МиБ — выбирается большее. При CUDA учитываются только окна передачи кадров, а GPU-буферы повторно в RAM не резервируются. Таким образом, свободная RAM используется и для больших результатов. Только остаток отправляется в файловый `mmap`; тип `IMAGE` и точность float32 сохраняются.

На этой машине кэш размещается в **`/mnt/comfy/alexz-video-cache`**, на SSD-разделе ComfyUI. Переопределение для обычного и dev-запуска:

```bash
ALEXZ_VIDEO_CACHE_DIR=/mnt/comfy/alexz-video-cache bash scripts/start_comfyui_dev.sh -- --port 8189
```

Если `/mnt/comfy` отсутствует на другой машине, используется `alexz-video-cache` в системном временном каталоге. Явно заданный путь имеет приоритет; при ошибке доступа скрытого переключения на другой диск нет. Путь определяется при загрузке модуля, поэтому изменение требует перезапуска процесса.

Перед декодированием Load Source Video печатает прогноз для известных последующих нод: число выходных кадров, кэш загрузчика/Camera, временные батчи быстрых этапов, каденс Camera, рабочую память и размещение по уровням. Параметры и seed Camera используются для расчёта того же числа кадров, что и при рендере. Прогноз сохраняется в `video_json.memory_plan`. Подробности и ограничения — в [гайде пайплайна](GUIDE_VIDEO_SILENT_FILM_PIPELINE.md#хранение-батчей-и-предварительная-оценка-памяти).

Чтобы убрать `--cache-none` из процесса, запущенного прежней версией скрипта, **закройте dev-сервер и запустите ярлык или скрипт заново**. Manager Restart сохраняет старые аргументы. Старые анонимные файлы кэша освободятся при завершении процесса; переносить их вручную не нужно.

Диагностика кэширования на установленном ComfyUI без сервера и пользовательских данных:

```bash
conda run -n p313-torch214-cu132 python tests/check_video_cache_lifecycle.py
```

Проверка использует короткий синтетический ролик, реальные ноды и исполнитель ComfyUI. Она сравнивает изображения при хранении в RAM/на диске, проверяет освобождение `mmap`, повторное использование загрузчика/Camera и повторный расчёт быстрых этапов. Адаптер `utils/video_cache.py` работает внутри ALEXZ_tools, не изменяя core-файлы, но использует внутренний интерфейс кэша установленного ComfyUI; после обновления core эту проверку следует повторить. Первым аргументом можно передать другой поэтапный workflow без bypass основных этапов.

## Ярлык рабочего стола

На текущей машине установлен ярлык **«ComfyUI Dev — ALEXZ_tools»** в системной папке рабочего стола. Он открывает GNOME Terminal, активирует `p313-torch214-cu132` и запускает этот скрипт с `--port 8189`. Интерфейс: `http://127.0.0.1:8189`. Терминал остаётся открытым после завершения процесса, чтобы видеть ошибки.

Ярлык не меняет обычный ярлык ComfyUI. Он содержит локальные пути этой машины и не включается в переносимый исходный код проекта. Для работы на 8188 используйте команду без --port из терминала либо отредактируйте локальный ярлык. Одновременно занятый порт другой экземпляр использовать не сможет.

## Параметры

| Параметр | Смысл |
|---|---|
| `--dry-run` | Печатает корень, разрешённые пакеты и точную shell-команду без запуска Conda/Python |
| `--extra-node ИМЯ` | Добавляет установленную папку или файл из custom_nodes; можно повторять |
| `--` | Всё дальше передаётся в main.py как аргументы ComfyUI |
| `--help` | Справка по скрипту |
| `ALEXZ_COMFY_ROOT` | Корень ComfyUI; по умолчанию определяется из расположения проекта внутри custom_nodes |
| `CONDA_EXE` | Путь к Conda; если не задан, conda ищется в PATH |

Environment всегда `p313-torch214-cu132`. Не требуется предварительная активация: используется `conda run --no-capture-output`, поэтому прогресс и логи видны в терминале. Proxy-переменные наследуются от терминала; локальные адреса добавляются в NO_PROXY.

Пример дополнительного пакета:

```bash
bash scripts/start_comfyui_dev.sh --extra-node was-node-suite-comfyui
```

Имена должны точно совпадать с папками установки. Скрипт не устанавливает отсутствующие зависимости. У старого двухнодового [workflow](../workflows/Видео-в-Хронику.json) есть сторонняя нода Seed из `was-node-suite-comfyui`; для него нужен этот пакет либо замена Seed на встроенный PrimitiveInt:

```bash
bash scripts/start_comfyui_dev.sh --extra-node was-node-suite-comfyui
```

## Decision helper

- Работа с новым Silent Film Pipeline: обычный dev-профиль из четырёх пакетов.
- Интеграция с одной дополнительной библиотекой нод: `--extra-node`.
- Полная пользовательская сборка, поиск межпакетных конфликтов или управление установленными пакетами: прежний обычный запуск.

Не передавайте вручную конфликтующие флаги белого списка: для расширения профиля используйте `--extra-node`.

## Интерпретация выходов

Перед запуском скрипт показывает корень ComfyUI и разрешённые пакеты. В конце загрузки в разделе `Import times for custom nodes` должны быть только они; сообщения `Skipping ... due to disable_all_custom_nodes and whitelist_custom_nodes` нормальны. Включённый через --extra-node пакет также появится в списке.

Логи выводятся в терминал, отдельный log-файл скрипт не создаёт. Режим `--dry-run` не проверяет работоспособность импорта пакетов — только наличие путей и команду запуска.

## Типовые ошибки и решения

| Симптом | Решение |
|---|---|
| main.py не найден | Проект находится вне custom_nodes: задайте ALEXZ_COMFY_ROOT |
| Отсутствует VideoHelperSuite | Установите зависимость обычным способом; dev-запуск не меняет установку |
| Conda не найдена | Добавьте Conda в PATH или задайте CONDA_EXE |
| Порт уже занят | Остановите предыдущий экземпляр или передайте --port 8189 |
| В открытом workflow отсутствуют другие ноды | Загрузите workflow проекта либо добавьте нужный пакет через --extra-node |
| Manager отсутствует | Проверьте установленную папку comfyui-manager и ошибки её импорта; в базовом профиле она уже разрешена |
| После возврата к обычному запуску нужны остальные расширения | Запустите прежний start_comfyui.sh без dev-флагов: расширения не отключались на диске |

## Производительность

Экономится время импорта исключённых custom nodes и их prestartup scripts. Инициализация Python, PyTorch, ComfyUI core, GPU и четырёх разрешённых пакетов остаётся. Конкретное ускорение зависит от установки; CPU-проверка старта не является замером времени полноценного GPU-запуска.

Для проверки импорта без сервера и выделения GPU-памяти можно выполнить:

```bash
bash scripts/start_comfyui_dev.sh -- --cpu --quick-test-for-ci --disable-auto-launch
```

Этот режим проходит начальную загрузку нод и завершает процесс до запуска сервера. Он не проверяет рендер workflow. При разработке обычный dev-запуск сохраняет CUDA: `--cpu` нужен только для такой диагностической команды.
