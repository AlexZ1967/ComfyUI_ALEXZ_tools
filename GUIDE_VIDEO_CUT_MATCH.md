# Match Video Cut Point — Guide

## Назначение
Поиск лучшей пары кадров для стыка двух видео: хвост `video_a` и начало `video_b`.

## Когда использовать
- Когда второе видео является продолжением первого (например после генерации в Kling/Veo).
- Когда нужно выбрать кадры реза и оценить уверенность стыка.

## Минимальный сценарий (3 шага)
1. Подайте `video_a` (исходник) и `video_b` (продолжение). В ноде доступны две отдельные кнопки: `choose video_a to upload` и `choose video_b to upload`.
2. Задайте `search_tail_a` и `search_head_b` (например 120/120), выберите `metric`.
3. Используйте `best_frame_a_number` и `best_frame_b_number` как точки склейки.

## Параметры
| Параметр | Что делает | Рекомендация |
|---|---|---|
| `video_a` | Первое видео | Оригинальный клип |
| `video_b` | Второе видео | Сгенерированное продолжение |
| `search_tail_a` | Сколько последних кадров A анализировать | 60-300 обычно |
| `search_head_b` | Сколько первых кадров B анализировать | 60-300 обычно |
| `metric` | Метрика сходства | `mse` быстрее, `ssim` устойчивее, `lpips_*` качественнее/медленнее |
| `normalize` | Нормализация A->B перед сравнением | `none` быстрее, `mean_std` полезно при сдвиге света |
| `top_k` | Кол-во лучших пар в JSON | 3-5 для ручной проверки |

## Decision helper
- Нужна скорость -> `metric=mse`, диапазоны 80-150.
- Есть сдвиг яркости/контраста -> `metric=ssim`, `normalize=mean_std`.
- Нужна максимально визуальная близость -> `metric=lpips_alex` или `lpips_vgg`.
- Слишком долго считает -> уменьшите `search_tail_a/search_head_b`.

## Интерпретация выходов
- `best_frame_a` / `best_frame_b`: лучшие кадры пары.
- `best_frame_a_number` / `best_frame_b_number`: индексы кадров для реза.
- `match_json`: детали поиска, `top_k`, `confidence` и подсказка по склейке.

Пример ключевых полей:
```json
{
  "best": {"frame_a_number": 498, "frame_b_number": 3, "score": 0.012, "confidence": 0.21},
  "cut_hint": {"cut_at_a": 498, "cut_from_b": 3, "blend_window_frames": 8}
}
```

## Численные ориентиры качества
- `confidence > 0.20` — стык обычно надёжный.
- `confidence 0.08..0.20` — средняя уверенность (проверьте `top_k`).
- `confidence < 0.08` — неоднозначный стык, расширьте диапазон поиска.

## Типовые ошибки и решения
- Медленно: уменьшите диапазоны поиска и/или перейдите на `mse`.
- Плохой стык при хорошем score: попробуйте `ssim`/`lpips_*`.
- Ошибка ffmpeg: установите `ffmpeg` в PATH (используется для чтения хвоста `video_a`).

## Производительность
- Сложность примерно `tail_a * head_b`.
- Для `lpips_*` применяется двухпроходный поиск (coarse MSE + refine LPIPS).
- Оптимальный практический диапазон: 80-300 кадров на каждую сторону.
