# Find Closest Video Frame — Guide

## Назначение
Поиск наиболее похожего кадра видео по изображению-референсу.

## Когда использовать
- Нужно найти в видео кадр, максимально близкий к заданной картинке.
- Нужно оценить качество совпадения и получить топ кандидатов.

## Минимальный сценарий (3 шага)
1. Подайте `image` и `video`.
2. Поставьте `max_frames` (например 200) и выберите `metric`.
3. Используйте `best_frame` и проверьте `scores_json.best` + `scores_json.top_k`.

## Параметры
| Параметр | Что делает | Рекомендация |
|---|---|---|
| `image` | Целевой кадр | Референс для поиска |
| `video` | Видео для поиска | Файл из input |
| `max_frames` | Сколько последних кадров анализировать | `0` = всё видео; 100-500 обычно достаточно |
| `metric` | Метрика сходства | `mse` быстрее, `ssim` устойчивее к свету, `lpips_*` качественнее и медленнее |
| `normalize` | Нормализация кадра к референсу | `none` быстрее всего, `hist` самый тяжёлый |

## Decision helper
- Важна скорость -> `metric=mse`, `normalize=none`, `max_frames` ограничить.
- Есть сдвиг по яркости/контрасту -> `metric=ssim` или `normalize=mean_std`.
- Нужна максимальная визуальная близость -> `metric=lpips_vgg`.
- Компромисс качества/скорости -> `metric=lpips_alex`.

## Интерпретация выходов
- `best_frame`: лучший найденный кадр.
- `best_frame_number`: номер лучшего кадра (0-based).
- `scores_json`: включает `best`, `top_k`, coarse-оценки и (для `lpips_*`) refine-метаданные.

Пример ключевых полей:
```json
{
  "best": {"index": 328, "score": 0.114, "confidence": 0.23},
  "top_k": [
    {"index": 328, "score": 0.114},
    {"index": 327, "score": 0.121}
  ]
}
```

## Численные ориентиры качества
- `confidence` (0..1): `>0.20` хороший отрыв лидера, `0.08-0.20` средне, `<0.08` неоднозначно.
- Для `mse`: `<0.01` обычно близко, `0.01-0.03` средне, `>0.03` слабое совпадение.
- Для `ssim` (если используете как основную метрику): чем меньше distance-оценка в `score`, тем лучше.

## Типовые ошибки и решения
- `No frames processed from video`: проверьте файл/кодек и `max_frames`.
- При `max_frames > 0` ошибка про ffmpeg: установите `ffmpeg` в `PATH`.
- Совпадение плохое: увеличьте `max_frames`, попробуйте `ssim`/`lpips_*`, включите нормализацию.
- Слишком медленно: уменьшите `max_frames`, используйте `mse`.

## Производительность
- LPIPS самый тяжёлый; в ноде уже используется 2-pass (coarse + refine).
- Ограничение `max_frames` обычно даёт самый большой прирост скорости.
